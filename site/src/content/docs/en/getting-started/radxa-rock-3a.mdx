YStreamer also runs on the **Radxa ROCK 3A**, a board built around the
Rockchip RK3568. It is **experimental**: the goggles link and the HDMI output
use the board's own USB controller and video hardware through the same code as
on the Pi, but far fewer people have run it there. The rest, the web
interface, streams, recordings and camera settings, works the same.

<Admonition type="info" title="What's different from the Pi">
  - **No ready-made image.** Install on Armbian with the install script. - **The
  goggles go into the upper USB 3 port**, with the board's OTG switch on DEVICE,
  not into a USB-C port. - **The board is powered through its own USB-C port**,
  which the goggles don't need. - **No Wi-Fi hot-spot** unless the board has a
  Wi-Fi module. Ethernet works as it does on the Pi. - **No [record
  button](/docs/using/record-button) and no reset pin**: the header's pins are
  numbered differently. There's no reset file either, since Armbian's card has
  no partition another computer can write to. Run `sudo ystreamer reset` over
  SSH instead. - **No "throttled" readings** on the Performance page; those come
  from the Pi's firmware.
</Admonition>

## What you need

- A **Radxa ROCK 3A** with Armbian's **Trixie, vendor kernel, minimal** image,
  from [dl.armbian.com/rock-3a](https://dl.armbian.com/rock-3a/). It has to be
  the **vendor** kernel: the "current" (mainline) images have no Rockchip
  video decoder, so the video would be decoded in software. Armbian has no
  Trixie desktop image with the vendor kernel, and YStreamer doesn't need one.
- A **USB-C power supply** with Power Delivery, 9 V or more and 18 W or more,
  into the board's USB-C port. Unlike the Pi's, that port is for power only
  here.
- The goggles cable: a **USB-C plug to USB-A socket OTG adapter** on the
  goggles, then a **USB-A to USB-A cable** from it to the board's **upper
  USB 3 port**, the one beside the OTG switch. The adapter always goes on the
  goggles' side.
- An HDMI cable and a screen, if you want the picture on one.

## Set the board up

1. Flash the Armbian image, boot the board and go through Armbian's first
   login (root password, your user, time zone), with a screen and keyboard or
   over SSH.
2. Set the **OTG switch** beside the upper USB 3 port to **DEVICE**. In the
   HOST position the goggles see nothing at all.

## Install

The [install script](/docs/getting-started/install-script) recognises the
board. Over SSH:

```sh
curl -fsSL https://ystreamer.yarosfpv.com/install.sh | sudo sh
```

On the ROCK 3A it also:

- adds Radxa's package repository and installs `librockchip-mpp1`, `librga2`
  and `gstreamer1.0-rockchip1` from it, which decode and encode in hardware.
  Armbian doesn't carry them. The repository is pinned to those three, so
  nothing else of Radxa's, kernels least of all, ever installs from it;
- hands the wired network from Armbian's own setup (netplan and
  systemd-networkd) to NetworkManager, which YStreamer's network settings
  work through. That takes effect at the next boot; the SSH session the
  install runs in stays up.

Then **reboot**:

```sh
sudo reboot
```

The board may come back on a different IP address, so open
`http://<hostname>.local`, with the board's hostname, rather than the old
address. Connect the goggles and switch them on. The **Logs** page shows
"Link is live", and HDMI shows the stream.

Updates from the web interface install the same package the Pi gets.

## If something's wrong

- **"no USB device controller" in the logs**: the OTG switch is on HOST. Set
  it to DEVICE and reboot.
- **The goggles don't connect**: try another OTG adapter; some leave out the
  resistor that tells the goggles they're facing a host. Power the board
  first, then the goggles, then the air unit.
- **"decoding with avdec_h264" in the logs**: the hardware decoder wasn't
  found, and the video is decoded in software. `uname -r` should end in
  `-vendor-rk35xx`; if it doesn't, flash the vendor image. Then
  `apt-cache policy gstreamer1.0-rockchip1` should show a version; if it
  doesn't, run the install script again. "decoding with mppvideodec" means
  the hardware decoder is in use.
- **`gst-inspect-1.0 mpph264enc` finds nothing**: run it with `sudo`. The
  video hardware is only open to root, and YStreamer runs as root.
- **Can't find the board after the reboot**: it got a new address from your
  router. `<hostname>.local` finds it, as does the router's list of devices.

## Undoing it all

```sh
sudo apt remove ystreamer
sudo rm /etc/apt/sources.list.d/ystreamer-radxa.sources \
  /etc/apt/preferences.d/ystreamer-radxa /etc/apt/keyrings/ystreamer-radxa.asc
```

To give the wired network back to Armbian's own setup, from the next boot:

```sh
sudo mv /etc/netplan/10-dhcp-all-interfaces.yaml.ystreamer-off \
  /etc/netplan/10-dhcp-all-interfaces.yaml
sudo systemctl enable systemd-networkd
sudo systemctl disable NetworkManager
sudo reboot
```
